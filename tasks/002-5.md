# 002-5: what any continuation of a history can do to each page figure

The page (outcome 002, `outcomes/002.md`) shows a lawsuit's effect on a loan's collections, timing and exposure. Its
figures come from an answer-first walk (`design/002-answer-first.md`): likely histories walked exactly, the rest
sampled. Each figure carries a range that must be true: it tells the reader whether a difference between figures is
real or the method's sampling, so a range claiming more certainty than it has would mislead a credit decision. A valid
range needs, for each point where the walk began sampling, a floor and a ceiling on what any continuation from that
point can give each figure, per operating draw, from the line's own rules, never from what the samples happened to
show. That is this task.

Write `continuation_bounds(line, t, ev, day)` in `app/analysis/continuation.py`: given one history's trajectories `t`
(`app/analysis/engine.py`, `Trajectories`, on some draws), its event cash `ev`, and per draw the day `day` before which
every continuation shares this history's event cash, return for every figure in `page.path_scalars` (funded, due,
collected, unpaid, past_due, frozen_due, not_yet_due, petition_p, clawback, stayed, peak_outstanding,
avg_outstanding, atm_proceeds, offering_proceeds) the per-draw lowest and highest value that figure can take on any
history the event model can produce (the walk's questions and answers, booked by `app/analysis/events.py`) whose
event cash equals `ev` on days before `day`, whichever answers it takes from `day` on. Per draw means per
trajectory, before `path_scalars` averages over draws: work out from the code how each figure is computed from a
trajectory (`core._scalars`, `core.Reduction.add`, `page.path_scalars`). The bounds must depend only on `t`'s values
on days before `day`, the line (operating draws, limits, routed invoices, fees, processing mode) and `ev` before
`day`, so that every history sharing that prefix gives the same bounds; say so in the docstring and test it.

The engine is causal (a day's figures depend on events up to that day), so before `day` a continuation's trajectory
equals `t`; from `day` on, find what bounds it from the rules: for example collections only add to what is collected
before `day`, and what can still be collected is bounded by what is owed at `day` plus the contractual amount of every
invoice that can still be funded; a petition can only happen once; `app/analysis/stress_search.py` derives a ceiling
on what is owed at any date (`exposure_bound`) that may serve. Read the engine's rules rather than assume them
(`app/analysis/engine.py` module docstring, `limits`, the funding test and collection order under both net and daily
processing, `app/analysis/processor.py` for daily). Equity proceeds come from the event cash, not the engine: bound them
from the offering rules in the event model (`app/analysis/events.py`, the offering and ATM mechanics and their limits);
if a figure has no ceiling that truly holds, return none for it and say why, rather than a guess (the range
arithmetic then shows that figure without a range).

Tight matters: a range's width is the probability of the unwalked part times the gap between floor and ceiling, so a
loose ceiling makes every range wide. But true matters more.

Test the property directly on real histories: walk a small complete tree of the real case (few draws, short horizon,
as `tests/test_stress_search.py::test_every_history_of_walked_tree_is_below_bound` does), run the engine on every
history, and for every pair of histories (A, B) and every draw, with `day` the first day their event cash differs on
that draw (the horizon where it never does), check every figure of B lies within the bounds computed from A. Report
how tight the bounds are on that tree (ceiling minus floor against the figures' spread). Keep local runs to a few
minutes; put anything longer in `var/diag/002-5/run.txt`. The coordinator is changing the walk and the range
arithmetic at the same time (`app/disputes/answer_first.py`, `app/analysis/page.py`, a new sampling module): keep to
the new module and its tests.

Done: `continuation_bounds` for every figure, each bound justified in its docstring against the code that makes it
hold, and the pairwise property test passing on a real walked tree.
