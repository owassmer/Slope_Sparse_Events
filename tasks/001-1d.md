# 001-1d The prototype of the dated shared-state walk, measured

Build part 2 of `tasks/001-1c-design.md`: the prototype walk and its local comparison, exactly as the design's last
section describes, on the same roots. Report in `tasks/001-1d-result.md` and stop there; the production walker,
pool and reduction stay as they are for now.

Three things decide whether this walk is fast and not merely correct, so measure each plainly:
- The current walk handles all 512 draws as arrays at once. Sharing states within one draw only can lose more to
  per-draw loops than it gains from sharing. Measure both ways if needed: per-draw, and identical transitions
  batched across draws.
- Running minima, first-floor dates and preference-window collections differ by route even where the future is
  shared. Measure how many distinct payloads reach each shared state.
- Later questions read earlier events. Measure how many distinct states remain once those tags are in the key,
  against how many there would be on cash and obligations alone.

End with the projection for the full tree, the time it implies on one machine and on the GitHub fleet, and what
part of the work dominates. No cloud and no judgment calls.
