# 001-1e Each chain says what it decides next, and when, without deciding it

The dated shared-state walk in `tasks/001-1c-design.md` needs one thing the engine cannot do today (see
`tasks/001-1d-result.md`): from a state, list every chain's next unresolved decision and its date on each draw
without booking any answer. Today `Chain.advance` finds a date by stepping a clone with an answer, and the walk
replays `_trace(s.steps + (c,))` per candidate.

Make that question answerable: for a given state, the litigation, distress, listing and notes chains each report
their next decision, its date per draw (or that none is pending on that draw), read-only. Same-day ties follow the
engine's existing order (a levy-day response before its levy, the floor before cash-out). Nothing about amounts,
dates or booking rules changes.

Show it is right on today's three failures: from the saved prefixes, the earliest decision it reports on each
draw is the one the dated facts say comes first (the day-96 ripe response before the day-155 floor, the earlier
levy before the notes' ripe payment, the day-74 set-aside before the day-77 floor on draw 279). Show it is cheap:
the time of one call against the replays the current walk makes to pick its next decision from the same state.
Commit with tests. No cloud and no judgment calls.
