# 002-3: the page shows each figure's interval and says who answered

The page (`/runs/<run>` in the viewer, `app/web/static/page.js` and `app/web/templates/page.html`, data from
`page.json`) is what Russell reads: a lawsuit's effect on a loan's collections, timing and exposure, beside the
business's ordinary ups and downs, with the judgments he can change. Outcome 002 (`outcomes/002.md`) builds it from an
answer-first walk (`design/002-answer-first.md`): the likely histories are walked exactly, the less likely sampled, so
each expected figure is now an estimate with a 99% interval from that sampling, which Owen asked to be shown as such.

What the payload already carries (`page_payload` in `app/analysis/page.py`):
- `meta.replicates`, `meta.t99`, `meta.intervals` (per tile key: figure, low, high under the judgments as answered);
- `paths.divisor` and `paths.replicate` per path; page.js's `pathProbs` already divides by the divisor, and
  `interval(probs, key)` in page.js gives the 99% interval of an expected figure under any judgments, so when Russell
  changes a judgment the interval moves with the figure;
- `meta.judgments` is "stand-in" when the seeded stand-in judge answered, with `meta.judgments_note` saying what that
  means: the run shows the method and is no judgment about the case.

Make the page show, for every expected figure it draws from the paths (the tiles and their comparisons), the interval
beside it in the page's own style, labelled as the range from sampling the less likely histories; update it whenever a
judgment changes. Where an interval is narrower than the figure's rounding, say so rather than printing a zero-width
range. Where `meta.judgments` is "stand-in", say so plainly and prominently, in the note's words, wherever the page
attributes answers to the judgment model. Percentile figures (P5, P95) are not intervals of this kind; leave them as
they are.

Build a page to look at with `uv run slope run akoustis_20240514` (about 30 minutes; it writes a run under var/runs)
or, faster, use the run already built there if one exists; serve it with `SLOPE_RUNS_ROOT=var/runs uv run slope viewer`
or through drive. Use the page as Russell would: change a judgment and see the figure and its interval move. Another
worker is adding a `stress` block to the payload in `app/analysis/page.py` at the same time: do not change that file;
if the page needs something more from the payload, say so in your report.

Done: in the running page, every expected figure shows its 99% interval and moves with it when a judgment changes,
and a stand-in run says so where answers are attributed.
