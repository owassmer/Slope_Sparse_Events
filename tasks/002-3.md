# 002-3: the page shows each figure's range, the worst path found, and who answered; changing a judgment works

The page (`/runs/<run>` in the viewer: `app/web/static/page.js`, `app/web/templates/page.html`, data from `page.json`,
the server's reweight in `app/web/app.py` and `page.reweight` in `app/analysis/page.py`) is what Russell reads: a
lawsuit's effect on a loan's collections, timing and exposure, beside the business's ordinary ups and downs, with the
judgments he can change. Outcome 002 (`outcomes/002.md`) builds it from an answer-first walk
(`design/002-answer-first.md`): the likely histories are walked exactly and the less likely sampled, so each expected
figure is an estimate with a range from that sampling, which must be shown as such, beside the worst feasible history
found, and changing a judgment must move the figures and their ranges.

What the payload carries now (`page_payload`):
- `meta.replicates`, `meta.intervals` (per tile key: figure, low, high at the run's judgments); `paths.divisor` and
  `paths.replicate`; page.js `interval(probs, key)` returns an expected figure's range under any judgments, and
  `pathProbs` already weighs each path by its divisor. How the range is computed will change (the design note's last
  sections); the page must get it from `interval()` only, so that change does not touch the display.
- `meta.judgments` is "stand-in" when the seeded stand-in judge answered, with `meta.judgments_note` saying what that
  means: the run shows the method and is no judgment about the case.
- `stress`: the worst feasible history the search found (`worst_found`: its sequence in the page's words, its figures,
  the draws it is feasible on), how it was searched, and the ceiling no feasible history can exceed (`bound`), with
  notes in plain words that it is the worst found, not claimed to be the worst there is.

Make the page:
- show, for every expected figure it draws from the paths (the tiles and their comparisons), its range beside it in
  the page's own style, labelled as the range from sampling the less likely histories, updated whenever a judgment
  changes; where a range is narrower than the figure's rounding, say so rather than print a zero-width range;
- say plainly and prominently, in the note's words, when the stand-in answered, wherever the page attributes answers;
- show the worst history found and the ceiling beside the probability-weighted figures, in the payload's own words,
  never as a probability-weighted figure;
- work when a judgment is changed, the server's reweight included. On the lead run (`akoustis_20240514-agent_plus_jev-
  20260928T052641Z`) changing a judgment gave the server error `int('')` in distress_day, and the economic-assumption
  choices gave server errors in a fresh checkout; find whether either happens on an answer-first run and fix what does.
Percentile figures (P5, P95) keep their current form.

Build a page to use with `uv run slope run akoustis_20240514 --tau 0.05 --replicates 2` (a few minutes; it writes a
run under var/runs) and serve it with `SLOPE_RUNS_ROOT=var/runs uv run slope viewer`, or through drive. Use it as
Russell would: change judgments, read the figures, ranges and the worst history. Another worker is changing the cash
analysis (`app/analysis/core.py`) at the same time: do not change that file; if the page needs something more from the
payload, add it in `page.py`.

Done: in the running page, every expected figure shows its range and both move when a judgment changes, the worst
history found and its ceiling are shown, a stand-in run says so where answers are attributed, and changing a judgment
and choosing an economic assumption give no server error.
