# 002-7: the equity block, compiled for one draw

The product is moving to an exact evaluator (`design/002-exact-evaluator.md`; read it whole, especially "The frame"
and "Port order"): the whole tree of what can happen in the lawsuit, walked one operating draw at a time, depth
first, in numba, with the state saved and restored at each decision. It is how the page's figures become exact
instead of sampled, on a laptop in under an hour. Today's Python (`app/analysis/events.py`, `events.Chain`) is the
definition while both exist; each area is ported against it and must agree with it exactly, on every draw, every
field.

What exists to build on (read each):
- `app/exact/fields.py`: where each part of one draw's state lives (scalars `S`, per-day `D` and `P` arrays); each
  area owns a block (yours: scalars from `S_EQUITY`, per-day int64 from `D_EQUITY`, per-day float from `P_EQUITY`).
- `app/exact/core.py`: the chain's core for one draw (the judgment's timeline, the amount owed `owed_at`, `live`,
  `mark`), compiled, already identical to the Python.
- `app/exact/export.py`: a Python Chain's state on one draw in that layout.
- `app/exact/oracle.py`: random complete histories of the real case (`style="long"` reaches levies, defaults,
  cash floors, offerings) and the Python's reference.
- `tests/test_exact_core.py`: how a port is checked, step by step (wrap `Chain.step`, export the state before,
  run the compiled step on it, compare with the Python's state after, and compare the compiled accessors with the
  Python's at many days).

Your area: the company's equity (QUESTIONS_20240514 §2.6) as `events.Chain` books and reads it: the share price
(`price_owed`, `_price_owed_grid`, `_reprice`, `share_price_on`; `app/analysis/share_price.py`; the compiled
`app/analysis/k_owed.py` kernels), the at-the-market sales under the baby-shelf limit (`_atm_schedule`,
`_atm_rebook`, `app/analysis/baby_shelf.py`'s `atm_book` and `capacity`, `app/analysis/k_atm.py`), the share ledger
(`atm_shares_to_date`, `atm_to_date`, `ledger_left`, `_offer_shares_on`, `_lockup`), the offerings (`offering_price_x1e4`,
`offering_terms`, `shelf_capacity`, `offering_pending_on`, `offering_bound_reached`, `offering_available`,
`offer_available`, `offer_shortfall`, `initiate`, `_close`, `offering_outcome`, `offering_day`), and `option_group`.
Read every one of them, and what they call, whole, before writing anything.

Write `app/exact/fields_equity.py` (your block's fields, each naming the Python it holds), `app/exact/equity.py`
(the compiled functions, one per Python method, each reproducing it on one draw), `app/exact/export_equity.py` (the
Python Chain's equity state on one draw in your layout) and `tests/test_exact_equity.py`. The Python keeps lists
(`_offers`, the at-the-market arrays); hold them in fixed-capacity tables with counts in your scalars, and say the
capacities you chose and why they cannot be exceeded on this case (the offering bound is two initiations).

Cash: some of these read the company's available cash (`cash_at`, `processing_balance`, through `Chain.cum`, which
runs the loan engine over the whole horizon on the event cash booked so far). Do not port that: take what they read

the caller. In your tests the caller passes the Python Chain's own (`chain.cum()[r]`, `chain.basis.need[r]`, ...);
in the evaluator a forward run of the line from the current state will. The at-the-market booking writes into the
event cash (`cash`, `kinds["inflow"]`): write those into the D arrays as the Python does.

What must hold, on random real histories (`oracle.histories`, both styles, several seeds, on a few draws): after
every step of every history, each compiled accessor equals the Python's on every draw at many days (the share price,
ledger left, offering terms, offering available, offer available, the option groups); and every step that books in

payment or a petition), run compiled on the state exported before it, gives exactly the Python's state after it on
your fields and the event cash. Floats exactly as the Python computes them (no fastmath; the same operation order).
Report what you checked (histories, steps, draws, accessor reads) and anything in the Python that a per-draw state
cannot hold.
