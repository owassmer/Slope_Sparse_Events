# 001-1h The walk never skips a decision: checked on its own output

Matching the chronological walk's histories against the current walker's cannot prove the new walk right, because
the current walker is the one known to be wrong. What decides it is an invariant on the new walk's own output: on
every history it emits, at every decision it asks, no chain had a pending decision dated earlier on that draw that
went unasked, and no decision the dated facts make due inside the horizon is missing from the history. Same-day ties
follow the engine's existing order.

Write that check over a walk's emitted histories, using the dated facts the walk already records and the frontier
from 001-1e. Run it on the saved roots. One case to settle by it: on `none279` the current walker asks a stay-window
settlement offer (`settle I4`, day 112, about $2.1M by the chronological walk's own answers) that the chronological
walk never asks. Either the check shows the new walk skips it, and you fix the walk where the cause lives with a test,
or it shows why it is not due there, in one dated sentence.

Run one root locally to build the check; put the full set of roots in `run.txt` (one command per line), commit, and
stop, and the coordinator runs them on GitHub. The goal is a walk we can trust without an oracle, so it can be made
fast next; don't account for every unshared history. No cloud and no judgment calls.
