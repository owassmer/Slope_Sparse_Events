# 001-1f A walk that always asks the earliest decision

With `Chain.next_decisions` (001-1e), write the walk loop from `tasks/001-1c-design.md`'s scheduling rule: from a
state, ask on each draw the earliest pending decision across all chains, split the draws whose earliest differs,
branch over every feasible answer, book it with the existing engine, and repeat until no decision is pending. The
existing question construction (situation classes, offered answers, grouping) and booking stay as they are. No
state sharing yet: this walk lists every history, like today's.

Run it beside the current walker on the saved roots (`var/diag`, the prefixes in `tests/test_dated_answer_domains.py`
and `tests/test_ripe_after_levy.py`, the replay roots in `var/diag/rewalk_other.py`): zero infeasible answers,
probabilities summing to 1 on every draw under a few explicit synthetic answer distributions, the same cash per
draw where the current walker is right, and each difference explained by a date. Report paths and time for both
walkers on each root. Keep it beside the current walker; do not switch production to it yet. No cloud and no
judgment calls.
