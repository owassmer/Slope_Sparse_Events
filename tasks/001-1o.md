# 001-1o Measurements that answer within twenty minutes

Every `run.txt` line on GitHub is now stopped after 20 minutes (`RUN_MINUTES`), and what it wrote by then is uploaded.
`tools/measure_chronological.py` and `tools/check_question_futures.py` write their results only when they finish, so a
stopped line answers nothing.

Make both write as they go: each history's measurement or check result appended to a JSONL file in `var/` as it is
produced, a summary rewritten every minute or so (histories so far, time, violations by question node with one dated
example each), and a clean final summary when stopped by SIGTERM. Then put in `run.txt` the runs that answer the open
question: which questions carry their future, and how often, over the current walker's whole tree from the review
date. Several draws, each its own line, each answering within its 20 minutes. Check the streaming locally on one
draw for a minute. No cloud and no judgment calls.
