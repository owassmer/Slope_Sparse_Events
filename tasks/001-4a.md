# 001-4a The chronological walk starts from the review date

The chronological walk (`app/disputes/chronological.py`) asks, on each draw, the earliest pending decision, and its
own checks (`tests/walk_order.py`: no decision skipped; `tools/check_question_futures.py`: no question carries its
future) hold on the roots it can start from. It starts only from a hand-seeded frontier (a stayed case before the
post-trial ruling), so it covers a few of the tree's 585 native roots. An earlier attempt to start it from the review
date stopped because the post-trial motions answer defined earlier settlement questions
(`tools/diagnose_chronological_start.py`). The post-entry legal state now drives what is pending (001-3a), and
settlement recurs on changes of state (001-3c), so that conflict is gone.

Make what is pending come from the state, from any state: the review date with nothing decided, or any native root's
prefix. The walk derives each chain's next unresolved decision from the state (litigation, settlement, stay,
registration, response, notes, listing, distress) and walks by the same rule. Answers, question classes and booking
rules stay as they are. In `tools/measure_chronological.py`, name roots by their prefix, not by their position in the
inventory, which shifts whenever the tree changes.

Show it on one draw: from the review date the walk runs for a few minutes with no skipped decision and no question
carrying its future. Put in `run.txt` the review-date walk on several draws, each line answering within 20 minutes
(write results as you go). No cloud and no judgment calls.
