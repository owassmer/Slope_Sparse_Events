# 001-1k What the whole tree costs with the chronological walk

The chronological walk (`app/disputes/chronological.py`) is now correct on the saved roots and checked by its own
invariant (`tests/walk_order.py`). Every root it has run on so far is a single draw. The decision it informs: can the
full 14 May tree be walked with it on GitHub's runners in a few hours, or does it first need the shared-state work in
`tasks/001-1c-design.md`?

Write the measurement, and put the runs in `run.txt` for the coordinator to send to GitHub (one root per line):
- The full tree's roots at the cut the production walk uses, built from the code (the walk's existing skeleton), with
  whatever measure of each root's size the skeleton gives.
- A sample of about 20 roots across that size range, each walked on all 512 draws with the chronological walk, timed,
  with its history count and peak memory, and the no-skip check on a few of them.
- The current walker on two or three of the same roots for comparison.

Run one small root locally to make sure the script works, and keep everything else for the runners. When the outputs
come back (the coordinator will give you a follow-up task), they become the projection; for now, stop once `run.txt`
is committed. No cloud and no judgment calls.
