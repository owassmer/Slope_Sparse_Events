# 001-9a Pool the walk's pieces and run the tree's gates

The full tree from the review date is being walked on GitHub's runners in waves of compact pieces (`slope walk-tree`;
each piece writes `events.pkl.gz`, `piece.json` and, if unfinished, `next.txt`; `piece_store.read_events` reads them).
The pieces end up as artifacts of several runs (`heavy-<n>`, about 18 GB in all), never on this Mac.

Write the pooling as a command that reads pieces one at a time from a list of run ids (`gh run download <id> --name
heavy-<n>`, deleting each after reading) and produces, small enough to bring back:
- the question catalog: every question the tree asks, deduplicated by key, with its class, facts and offered answers,
  and how many histories and draws reach it;
- the gates outcome 001 sets (`outcomes/001.md` is not in your workspace; these are they): coverage (every top
  partition and every continuation finished, each branch walked exactly once, no gaps or overlaps between pieces);
  probability (on each of the 512 draws, path probabilities sum to 1 under several random sets of answers); answers
  (every answer a history takes is offered by its question on that date); and a random sample of histories for the
  no-skip and no-future checks, reported separately.
Pieces may finish in different waves; the command takes all of them. Build and test it locally on a few pieces
(`var/compact-comparison/` has one; a few minutes of `slope walk-tree` on one or two partitions makes more), then put
in `run.txt` one line that pools a given set of runs, each step within 20 minutes or split. No cloud and no judgment calls.
