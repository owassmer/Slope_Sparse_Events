# 001 The 14 May page on a tree that is shown to be correct

Russell can open the 14 May Akoustis page served from a new recorded run built on the corrected step 9 tree, and
change a judgment and see the cash move. The page changes only where the new data forces it; revising the frontend
is the next outcome. Walk and pooling come first.

Before Clef answers anything, the tree passes:
- Coverage: every segment present exactly once; branches merged only where they book the same cash and lead to
  the same later questions.
- Probability: on each of the 512 draws, path probabilities sum to 1 under any set of answers.
- Answers: every answer a path takes is one its question offers on that date.
- Dated facts: every question's facts are as they stood before its own answer.
- Independent replay: an agent that did not write the code replays random whole paths from scratch through the
  plain engine (no prefix cache, merging or refinement) and finds the same cash, dates, question facts and offered
  answers as the pooled tree. Local CPU only, on a sample saved with the run.
- Questions read: the same agent reads 100 sampled rendered questions against the question rules and the purpose.
- Three traced paths: the same agent traces three complete paths in plain words (a filing, a settlement, a
  payment), each step against its rule in QUESTIONS_20240514.md. Owen reads them and says start.

Spending: AWS up to $30, reported at each stage. Clef only on Owen's start.
